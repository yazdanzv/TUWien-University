# TU Wien University Workspace Instructions

## Scope and precedence

- Apply these instructions throughout this university workspace.
- Read the relevant course documents and the complete assignment brief before
  starting work. Course policies, lecturer instructions, rubrics, and assignment
  requirements take precedence over this file.
- Preserve original assignment instructions and the meaning of the student's
  writing when editing.

## Academic writing

- Use natural, precise, professional academic English appropriate for
  university-level work; avoid robotic phrasing and needless complexity.
- Build clear, structured arguments supported by evidence.
- Preserve the author's claims, intent, and voice unless asked to revise them.

## Research and citations

- Prefer trustworthy scientific and primary sources where possible.
- Verify citations, authors, titles, publication details, and DOIs before use.
- Never invent references, data, experimental results, observations, or
  findings.
- Clearly distinguish established facts, interpretations, and assumptions.

## Programming and reproducibility

- Produce readable, maintainable, well-structured code and explain important
  implementation decisions.
- Use testing and validation appropriate to the task. Never describe unexecuted
  code as tested.
- Prefer reproducible experiments, explicit random seeds when relevant, isolated
  environments, and minimal dependencies.
- Separate source code, tests, configuration, datasets, generated outputs, and
  reports.

## Academic integrity

- Follow the applicable course and assignment AI-use policy.
- Do not fabricate experiments, observations, findings, sources, or execution
  evidence.
- Identify assistance or attribution requirements when the course policy calls
  for them.

## File and project management

- Keep folder organization clear and documentation concise.
- Do not overwrite original lecture files, assignment briefs, raw datasets, or
  submitted work. Create derived or revised copies instead.
- For each new assignment, use `assignments/assignment-NN/`, store the original
  instructions separately, and keep working files distinct from final submission
  files. Do not create placeholder assignments.
- For a substantial programming project, use a dedicated `projects/<name>/`
  directory with an appropriate README and `.gitignore`; separate source, tests,
  configuration, data, outputs, and reports.
- Use Git when it provides useful history, but do not create redundant nested
  repositories. Add a project-level `AGENTS.md` only for genuinely specialized
  requirements.
- Avoid unnecessary documentation and unrelated files.

## Skills

- Use an installed specialized Codex skill when it clearly matches the task, but
  verify availability first and do not force a skill into every task.
- Prefer the installed PDF skill for PDF reading, creation, inspection, or
  validation. Use available document, presentation, spreadsheet, and
  visualization skills when their artifact workflows are relevant.
- Do not install, reinstall, or duplicate skills unless the user explicitly asks.
